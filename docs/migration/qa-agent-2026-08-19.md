### Diagnosis order

`ELECTRON_DISABLE_GPU=1`, so DWM/GPU remains HUMAN). Core `player.position`
publishes at 250 ms while playing (~4 Hz). That is **not** a 30 Hz snapshot
clock. `lyrics.word` can fan out at the 50 ms clock into lyrics surfaces only.

Shared root for A/B: `applyExternalSnapshot` replaced `queue` on every
snapshot, so `useCurrentSong()` and PlayerBar chrome committed at snapshot
rate; progress/volume were controlled inputs without a local draft, so 4 Hz
authoritative echoes fought the thumb. Settings sliders already had a draft
and do not ride the player store — that matches Settings PASS / player FAIL.

C/D/E are **not** the same storm. Desktop Lyrics empty state was document
fetch fencing + ignoring `projection.currentLine`. Missing controls and Island
oscillation were Electron `-webkit-app-region: drag` on the full surface
eating pointerenter/leave (hover chrome is the documented parity, not a new
UI).

### After measurements (`qa-playback-ui` probe, GPU disabled)

| State         | rAF FPS | store Hz | IPC snapshot Hz | PlayerBar mutations/s                                          |
| ------------- | ------- | -------- | --------------- | -------------------------------------------------------------- |

| playing       | ~240    | ~4.2     | ~4.2            | ~279 (rAF DOM writes on the progress input; not React commits) |

session is therefore **not** proven as a 30 Hz React clock; it may still be

### Fixes

- Progress: local draft + pointer capture; visual clock via rAF DOM writes;
  authoritative snapshots do not overwrite an in-flight drag.
- Volume: local draft + `beginVolumeScrub` so echoes cannot snap the thumb.

  empty; skip word-only projection React replacement.

E2E: `e2e/electron/qa-playback-ui.spec.ts`. Full Electron suite **37 passed**
after these fixes. Do not mark UI-PERF / Desktop Lyrics / Lyrics Island

### DEFECT A — PLAT-02 toggle

Root cause: Electron Main had no `system_shortcuts_set_enabled` host handler,
so IpcRouter returned `host.denied` / “implemented by the host”. The Settings
toggle then reverted. Boot also registered shortcuts unconditionally (unlike
Tauri, which honors prefs). Native Wayland detection was already correct.

Fix: host handler + `createGlobalShortcutSession` (unregister-then-register,
per-accelerator conflict, no fake success, Wayland still throws the Tauri
message). Prefs apply only when `globalShortcutsEnabled` changes.

On this Windows agent, Electron `globalShortcut.register` succeeds for
`Control+Alt+F24` but returns false for the three FACT accelerators
(`Control+Alt+Space/Left/Right`) even outside Playwright. That is an OS
`RegisterHotKey` conflict, not unimplemented host. E2E asserts the handler is
implemented and surfaces `shortcutError` without crashing. Successful
register + restart restore is covered by desktop unit tests and still needs
HUMAN on a machine where those hotkeys are free.

### DEFECT B — Windows slider / progress / lyrics stutter

Root cause (measured in production path, not guessed CSS-first): Settings
`RangeControl` called `updateAppearance` → `app_preferences_set` on every
input; `preferences://changed` could hydrate over in-flight drag;
`SettingsPage` subscribed to the whole store; `PlayerBar` used
`usePlayerStore()` so every `positionMs` tick re-rendered chrome.

Fix: 200 ms coalesced persist for appearance/lyrics sliders (system/locale
immediate); ignore remote hydrate while a persist is pending; RangeControl
local draft + CSS `previewAppearance` during pointer capture; PlayerBar
progress/volume isolated with selectors. Visual effects were **not** removed.
E2E GPU is disabled (`ELECTRON_DISABLE_GPU=1`), so compositor/DWM cost
remains HUMAN.

Before: 8 appearance writes → 8 `app_preferences_set`. After: 8 writes → 1
IPC (`preferences-persist.test.ts`). Opacity restart E2E still passes.
