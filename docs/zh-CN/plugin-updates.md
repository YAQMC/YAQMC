# 插件更新与同版本替换

YAQMC 将更新视为已安装插件的事务替换。宿主先固定候选包和当前安装代次，完成解包、扫描、兼容性、依赖、提供器和权限检查，再等待目标插件空闲后停用旧实例。验证或启动失败时保留旧插件。事务日志和 `packages/<sha256>` 不可变目录支持进程退出后的恢复。

插件 ID 不变。发布信息包含严格 SemVer、`stable / beta / nightly` 渠道、仅用于展示的 build ID、递增 release sequence 和包 SHA-256。相同哈希不重装；同版本不同内容明确显示“同版本替换”；降级、渠道变化、新权限以及提供器或会话格式变化必须确认。无法解析为 SemVer 的旧版本仍可加载和手动替换，但不参与自动排序。

远程更新按插件绑定。发布者使用 Ed25519 对原始 UTF-8 JSON 字节签名，宿主同时检查插件 ID、HTTPS 清单地址、公钥、下载域名、有效期、序号和发布签名。插件清单不能新增宿主信任源。当前 `crates/yaqmc-core/src/plugin/updates/sources.json` 为空，因此真实源接入前界面显示“暂无远程更新源”。签名工具为 `scripts/plugin-release.mjs`，不生成或提交生产密钥。

更新界面显示候选版本、完整哈希、可信来源、渠道、权限差异、会话处理和播放影响。“稍后更新”等待目标插件连续空闲；“停止使用并更新”只停止该插件占用的播放源，不影响其他插件。未验证的本地包可手动替换，替换后暂停自动更新。

凭据继续使用现有凭据后端；组件 KV、缓存和普通设置进入暂存事务。提供器 ID 或 `sessionSchemaVersion` 改变时建立新的会话命名空间，不继承旧秘密，旧数据保留并需要重新登录。候选验证期间不执行第三方账号写操作。

宿主新增 `plugin_update_*` 接口和 `plugin://update-progress` 事件。接口只允许宿主和主窗口调用，插件、歌词窗口及本地 HTTP API 无权触发。当前交付包含本地事务、签名校验、故障恢复、隔离测试和发布者规范；生产远程源尚未上线。

`plugin_update_prepare` 也接受插件商店附件（`github: { owner, repo, releaseId, assetId }`），见[插件页面与插件商店](plugin-store.md)。商店安装包按未验证来源审核，来源记录为 `github:<owner>/<repo>/releases/<id>`；替换来自其他来源的同一插件 ID 时需要 `source-change` 确认，且永远不会成为可信更新源。

## 使用方式

1. 在插件卡片选择“更新 / 替换”，选择新的 `.yaqmc-plugin`。通过“添加插件”选择同 ID 包也进入相同审核；开发模式“重载”先准备目录快照。
2. 审核版本、渠道、构建标识、权限变化与登录处理。同版本不同内容、降级、渠道/会话变化、本地未验证来源都必须确认。相同 SHA-256 不重装、不重启。
3. 选择“稍后更新”等待占用结束，或明确选择“停止使用并更新”。暂停播放仍可能持有音源，自动流程不会中断它。关闭审核窗口不会取消已提交的后台任务；需要取消时使用“取消操作”。
4. 只有宿主内置真实可信来源后，才可确认仓库和签名公钥并启用空闲自动更新。首次确认默认启用，可在详情关闭；只跟随选定渠道。

相同插件 ID、提供器 ID、会话格式保留凭据、KV、缓存及设置。`sessionSchemaVersion` 默认 `1`；格式改变建立新命名空间并过滤旧秘密设置，普通界面设置保留。之后由用户明确重新填写的新秘密可提供给新会话。登录过期或第三方网络错误不等于安装失败。

## 发布规范

完整 JSON 结构及工具命令见[签名协议](../plugin-updates.md#signed-wire-format-schema-1)。发布记录的 `channel`、`buildId`、`releaseSequence` 是顶层字段；包 manifest 中这三项放在可选的 `release` 对象内。包已声明时必须与签名记录一致。

外层封套严格包含 `keyId`、`payload`、`signature`，使用标准带填充 Base64。签名覆盖“域前缀 + 单个零字节 + 原始 UTF-8 JSON 字节”，不重新序列化 JSON。发布记录使用 `YAQMC-PLUGIN-RELEASE-v1`，清单使用 `YAQMC-PLUGIN-FEED-v1`。公钥为 32 字节，签名为 64 字节。

先对发布记录执行 `sign release`，把封套嵌入清单 `releases` 数组，再执行 `sign feed`；实际发布外层清单封套。递增 `sequence` 和跨渠道的 `releaseSequence`，更新 `expiresAtMs`。拒绝过期、序号倒退和同序号内容冲突。测试向量的公钥只用于测试，不能进入生产信任列表。

清单最多 1 MiB / 256 条发布记录。下载沿用现有包及解压配额，最多两个并发，连接超时 10 秒、无数据超时 30 秒、单包总超时 5 分钟；最多三次重定向，每一跳校验 HTTPS、允许的 origin 和公网地址。独立下载客户端遵循系统代理，不携带音源 Cookie 或认证头。代理属于用户网络信任边界。

## 接口与故障处理

`policy_get/set` 管理来源、渠道与策略，`check` 检查清单，`prepare` 固定候选快照，`apply` 仅消费已准备的 `operationId`，`status` 查询进度，`cancel` 取消准备/等待任务，`runtime_ready` 确认指定阶段与哈希，`editing` 续期设置编辑占用。TypeScript DTO 位于 `packages/yaqmc-client/src/protocol/plugin-updates.ts`，SDK manifest 类型位于 `sdk/plugin/src/index.ts`。主窗口通过事件及查询恢复丢失进度。

自动检查启动后延迟 30 秒，正常每 24 小时检查；失败退避最多一小时。自动应用要求连续闲置 30 秒、严格更高版本、同渠道、无权限和会话扩张。安装失败的发布记录暂停自动重试，用户可重新准备，或等新发布记录。进入停用阶段后不再接受取消。

事务日志配合原子安装指针实现恢复，并非把多个数据文件一次性原子写入。提交前失败恢复旧版本及本地数据；持久化提交后保留新版本并继续清理。显示 `update-committed-restart-required`、`update-committed-cleanup-pending` 或 `update-recovery-required` 时重启以恢复，未完成恢复前禁止该插件继续变更。策略损坏时停止远程更新并保留原文件，本地替换仍可用。

脚本 `activate` 支持 Promise；本地初始化完成后返回，拒绝或超时会回滚。验证阶段仅允许本地存储、读取设置、日志和 UI 注册，UI 效果提交后发布，不应在激活阶段强制依赖第三方登录或联网。宿主不执行插件迁移脚本，也无法撤销已经发生的第三方服务变化。
