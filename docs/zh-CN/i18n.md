# 国际化

> **简体中文** | [English](../i18n.md)

界面使用 `i18next` 与 `react-i18next`。资源位于 `src/locales/en-US.ts` 和 `src/locales/zh-CN.ts`，按
`common`、`navigation`、`pages`、`player`、`queue`、`lyrics`、`settings`、`errors` 分 namespace。
TypeScript 从英文资源推导合法键，中文必须满足相同递归结构，漏键和拼写错误会在编译期失败。

## 语言解析与持久化

偏好为 `system`、`en-US` 或 `zh-CN`，默认跟随系统。英文标签映射到 `en-US`，简体中文和新加坡中文
映射到 `zh-CN`，其他回退英文。显式偏好先同步写入 localStorage，让首次 React 渲染前就使用正确语言；
完整版本化偏好随后从 SQLite hydration。修改后无需重启，同时更新 i18next 和文档 `lang`。

早期浏览器缓存只是启动投影，SQLite `ui-preferences-v1` 才是原生事实源；`preferences://changed` 同步
Electron 主窗口与歌词窗口。

## 内容语言规则

界面语言只影响应用 chrome。歌曲、艺人、专辑和歌单名保持提供器原样，不自动翻译、罗马化或猜别名。
原文歌词、翻译和罗马音也是三个独立字段；Auto/Show/Hide 只决定展示，不改写 `LyricDocument`。

新增文案时：先加英文键，再在相同路径加自然简体中文；在展示边界用 `useTranslation(namespace)`；
提供器 ID、协议字段、技术日志和音乐元数据不能放进资源；数字用 `Intl`；影响 fallback、切换、无障碍或
错误码时补测试。Rust/HTTP 错误保持稳定技术契约，React 在 UI 边界翻译。
