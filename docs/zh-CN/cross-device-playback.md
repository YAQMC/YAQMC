# QQ 音乐跨设备续播实验

> **简体中文** | [English](../cross-device-playback.md)

桌面和 Android 原生播放器的设备图标提供此入口，需要当前 QQ 音乐配置已经登录。打开或刷新只读取同一账号另一端的近期播放快照，不改变播放状态。预览显示歌曲、队列数量和远端更新时间；确认后替换本机队列，从远端当前歌曲开头播放，再显式上报一次本机状态。

快照不含精确进度、播放模式、暂停标志或稳定设备标识，不能当作播放历史。实现要求有效歌曲 ID 和时间戳；按远端正数卡片有效期检查新鲜度，上限五分钟，无有效期时使用五分钟。队列最多加载 100 首，保留顺序和重复项，并确保包含当前歌曲。缺少元数据或不支持的歌曲类型会被省略并提示队列不完整；当前歌曲不可播放时阻止操作。若本机只能播放官方试听片段，则不发送上报。

当前固定使用 qm-api-rs `065a50c06606a2377ee8044c036ce3f659a914f0` 的 `GetOtherPlatCurrentPlaylist` 和移动端字段格式 `ListeningMusicReport`，Android 使用 Android CGI 配置及 QIMEI、GetSession 会话，桌面使用 Desktop 配置；设备标识按安装、配置和平台持久化，跨请求和重启复用。账号代次变化时清除缓存会话。时长和剩余时间使用毫秒，队列采用本机实际加载的队列。未使用时间单位尚未确认的 Windows 原生上报格式。

目前没有验证专用接管指令，也没有可以证明原设备暂停的回执。上报请求返回只能证明该调用已返回；SDK 的宽松回执解码不构成接管成功的依据。界面分别展示本机播放和上报结果，并要求检查另一台设备。此功能没有后台自动接管、原端暂停接收机制，也不自动重放结果不明的写入。

“向我的其他设备共享播放状态”默认关闭，按配置保存。两台 YAQMC 互相发现时需分别启用。Core 每三秒采样本机播放器，对完整歌曲的播放、暂停、跳转和队列变化上报一次，播放中每十五秒上报最新状态；官方试听不参与共享。关闭开关会取消待处理的共享请求，账号变化会清除旧上报状态。上报失败不影响本机播放，上报返回也不代表原端暂停。

真实微信登录配置的上报返回过业务码 `405`、`errmsg="wx login"`，但另一台设备仍能读取更新的歌曲和队列，因此该回执不能证明状态写入失败。YAQMC 保留“结果无法确认”，不重放同一次显式接管；启用共享时仍可采样并上报后续播放状态。实测原设备没有自动暂停。重启后恢复的队列必须实际加载音源，才可参与共享。

成功的空快照可能返回 `playList: null`。YAQMC 在 SDK 解码前仅为该请求将此字段转换为空队列，其他畸形队列类型仍报错。

`provider_device_playback_preview`、`provider_device_playback_takeover` 和 `provider_device_playback_sharing` 仅供主窗口调用，绑定完整提供器和配置身份。Core 保留一个有效期 30 秒的随机单次令牌；确认时核对配置、账号代次和有效期，再读取一次远端状态。歌曲或队列变化时要求重新预览。并发重复操作被拒绝，已消费令牌不能重放。

Core 在确认操作的远端请求前记录本机状态；播放器在队列写锁内核对会话、队列项、播放状态、进度跳转代次和播放模式后才替换队列。网络等待期间发生本机操作会使旧请求失效，正常播放时钟前进不会。播放失败或上报前发生账号、播放会话变化时不发送上报；认证失效会取消请求。上报结果不明时保留本机播放且不自动重试。

2026-11-17 真实 Windows 与 Android YAQMC 实测：两端同一微信登录账号，Android 的当前歌曲和 20 首队列可由 Windows 读取，并在 Windows 启动完整歌曲播放；Android 原端继续播放，没有自动暂停。反向在 Windows 已开启共享、完整歌曲实际播放时，Android 仍未读到可用快照。因此仅验证了单向续播，双向接管和原端暂停未通过。Android 系统返回键实测只关闭弹窗，不打断播放。账号切换和断网等分支有合成测试，未在真实已登录设备上执行破坏性验证。

后续互通验证可用官方客户端作一端对照：两端登录同一 QQ 音乐账号，YAQMC 两端均开启播放共享，并播放完整歌曲而非试听片段，再打开预览、确认续播，分别观察本机音频、上报结果及原端是否暂停。记录官方客户端平台和版本，测试桌面与 Android 对调、过期快照、退出账号、不可播放歌曲、重复点击、加载期间切歌和上报断网。YAQMC 两端的测试结果不能替代官方客户端互通验证。
