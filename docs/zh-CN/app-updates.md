# 应用内更新

> **简体中文** | [English](../app-updates.md)

设置中的“更新”区域检查 YAQMC 官方 GitHub Releases。启动 30 秒后开始后台检查，之后每天检查一次；后台检查只提醒。点击“下载、更新并重启”后，宿主下载并校验包、保存队列、等待插件事务完成，再安装和重启，无需第二次确认。下载期间继续播放；开始安装准备前可以取消。

## 支持范围

官方 Windows 安装版和便携 EXE，以及官方 Linux AppImage，支持 x64、arm64 自更新。deb/rpm、tar.gz、AUR、Git/本地构建及未知来源只提醒，请通过原分发渠道更新。Android 保持现有更新提醒。

本地优化构建或打包仍属于源码构建。宿主内嵌来源、完整 commit、tag 和架构，只有官方合法版本 tag 发布工作流会标记为官方 Release。运行时环境变量不能把本地构建变为官方包。历史可执行文件需要先手动安装一次包含新更新器的 Release。

“接收预发布版”默认关闭并在本地保存；开启后包含已发布的 beta/nightly 等合法 SemVer 预发布版本。关闭不会降级。只有严格更高版本才会更新；同版本不同 commit 不替换。草稿和 Git 分支新提交不属于更新候选。

## beta 用户如何更新

先安装一次包含新更新器的官方 Release，在**设置 → 更新**开启**接收预发布版**，再检查更新。例如 `0.1.2-beta.1` 用户能收到已发布的 `0.1.2-beta.2`，点击“下载、更新并重启”即可。关闭开关后保留当前 beta，等待更高的正式版（例如 `0.1.2`），不会退回 `0.1.1`。

从 CI 或 **Build artifacts** 下载的包、AUR 和本地 Git 构建只有提醒能力；需要先安装官方 Release 包才能在应用内替换。发布者通过 **YAQMC 发布**的版本 tag 发布，不能直接使用分支产物，详见[beta/nightly 发布步骤](ci.md#发布-beta-或-nightly)。

## 校验、安装与恢复

宿主固定 Release、资产、包型、应用架构、大小和 GitHub SHA-256，并在下载及安装前重新核验。匹配包缺失、资产变化或校验失败时拒绝安装。独立网络会话遵循系统代理，不携带音源 Cookie 或凭据；HTTPS 重定向只允许 GitHub 及其发布资产主机。包流式写入磁盘，取消或失败后清理不完整文件。

Windows 安装版使用 `electron-updater`、各架构独立元数据及 SHA-512 校验；已有发布者签名校验继续生效。当前官方未签名包使用官方 HTTPS 分发和哈希检查完整性，哈希不构成独立的发布者签名。

便携版和 AppImage 使用原生 `yaqmc-update-helper`：在原路径旁暂存新文件，等待旧进程退出，保留备份并替换，再启动新版。主窗口与 Core 就绪确认后提交；启动失败执行一次文件级回退并重新打开旧版。持久化日志支持中断恢复。NSIS 使用安装器自身的错误处理与重试。这些恢复机制不降级用户数据库，也不能撤销第三方服务操作。

用户数据、插件、凭据、设置和播放队列保留原位置。退出前 Core 阻止新的插件变更，并等待正在提交或回滚的事务结束；退出准备失败不替换应用。下载失败或取消后可从设置重试。

## 宿主接口

`host_updater_check`、`host_updater_status`、`host_updater_start`、`host_updater_cancel` 和 `host_updater_preferences` 为带类型、仅主窗口可调用的宿主方法；保留旧下载/安装接口。开始更新只消费宿主候选 ID，前端不能指定 URL、可执行文件路径或命令。长任务返回操作 ID，并通过 `host://update` 报告进度；设置页重进后查询现有状态。插件脚本、歌词窗口及本地 HTTP 调用方无权发起更新。

## Release 概述

后续发布正文由 `scripts/ci/release-commits.mjs` 生成，按提交顺序列出短 SHA、原始标题和链接。正式版以上一已发布正式祖先版本为基准；预发布以上一同版本线预发布为基准，没有时回退到上一正式祖先版本。首次发布列出完整历史。正文过长时链接完整 `COMMITS.md` 附件。下载说明放 `DOWNLOADS.md`，许可证、版权、对应源码和包校验文件继续保留；不改写历史 Release。

`scripts/ci/app-update-acceptance.mjs` 使用独立 QA 应用和配置验证真实包更新。通过 `YAQMC_UPDATE_HELPER_BIN` 指定对应系统和架构的辅助程序。Windows 原生运行；Linux AppImage 测试需要 Linux 桌面或虚拟显示环境，并保持 Chromium 沙箱可用。测试使用模拟会话和本地传输接口，不发布生产 Release。
