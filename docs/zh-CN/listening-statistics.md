# 收听统计

> **简体中文** | [English](../listening-statistics.md)

YAQMC 依据 Core 播放引擎在本机计算收听统计，不上传记录，也不会调用音乐平台的分析接口。在侧边栏打开
“统计”，可以查看滚动 7 天、30 天、365 天或全部时间的数据。

## 统计口径

只有同一播放会话处于 `playing`，且引擎播放位置正常向前推进时，才累计收听时长。暂停、缓冲、跳转、
音源恢复及单纯经过的 wall-clock 时间均不计入。

达到 30 秒或已知可播放时长的 50%（取较早者）即为有效播放；官方试听片段使用实际可播放时长。播放
引擎抵达 EOS 时，无论是否达到阈值，都记为完整播放。阈值前主动下一首/跳歌记为跳过，替换队列、退出
或停止记为停止；致命错误单独记录，已达到阈值时仍保留为有效播放并附带错误码。单曲循环每次 EOS
都会结束一条记录，再开始下一条。

页面显示有效收听时长、有效播放数、完整播放数、跳过率、每日趋势、常听歌曲/歌手/专辑、实际播放
音质和音乐平台分布。`playback_history` 继续作为有上限的最近歌曲快照；统计使用独立的
`listening_sessions` 数据集。

## 导出与删除

“导出 JSON”生成带版本号的汇总和会话记录；“导出 CSV”先写一行汇总，再写会话行。原生保存对话框
只会为指定渲染窗口、格式和精确路径签发一次性授权，渲染进程不能借此任意写文件。

“清空统计”需要二次确认，只删除收听统计。偏好设置、账号音乐库、提供器缓存、当前队列和最近播放
快照均保留。播放中清空会从零建立新记录，清空前累计的时长不会重新出现。

页面显示的数据库大小包含 SQLite 主文件以及活动中的 WAL/SHM sidecar。各平台目录见
[数据位置](data-locations.md)。

## 贡献者契约

统计由 Core 持有，通过类型化的 `statistics_snapshot`、`statistics_clear` 和 dialog-split
`statistics_export_to` 暴露。渲染端在现有 `api://event` 通道监听并节流处理 `statistics.changed`。
Provider 和 Electron Host 不得自行推断播放，也不得复制上游 API 路由。

每次播放器事件的记录开销为 O(1)。范围聚合扫描符合条件的本机记录，并使用结束时间、
provider/track、album 和 artist 索引。自动化存储门禁会用 100,000 条会话验证聚合查询。
