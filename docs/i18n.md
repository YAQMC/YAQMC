# Internationalization

The interface uses `i18next` and `react-i18next`. Resources are TypeScript objects in
`src/locales/en-US.ts` and `src/locales/zh-CN.ts`, grouped into `common`, `navigation`, `pages`, `player`,
`queue`, `lyrics`, `settings`, and `errors` namespaces. `src/i18next.d.ts` derives valid namespace and key
types from the English resource, while the Chinese resource must satisfy the same recursive shape. A missing
or misspelled key is therefore a TypeScript error.

## Locale resolution and persistence

The user preference is `system`, `en-US`, or `zh-CN`; `system` is the default. `src/i18n.ts` maps English
language tags to `en-US`, maps Simplified Chinese and Singapore Chinese tags to `zh-CN`, and falls back to
`en-US`. An explicit locale is cached synchronously in `localStorage` so i18next initializes in the correct
language before the first React render. The complete versioned preference document is then hydrated from the
existing SQLite settings store. Changing the preference updates i18next and the document `lang` attribute
without restarting the application.

The early browser cache is a startup projection, not a second source of truth. Native persistence remains the
SQLite `ui-preferences-v1` document, and `preferences://changed` keeps dedicated Tauri windows synchronized.

## Content-language policy

UI locale affects application chrome only. Song, artist, album, and playlist names remain exactly as supplied by
the active provider. The application does not translate or romanize metadata and does not infer alternate names.
If a provider later exposes canonical, localized, or romanized names, those must be separate domain fields and a
separate display preference.

Original lyrics, translations, and romanization also remain distinct normalized lyric fields. The `Auto`,
`Show`, and `Hide` presentation settings decide whether existing secondary text is useful and visible; they never
rewrite a `LyricDocument`.

## Adding or changing copy

1. Add the English key under the narrowest existing namespace.
2. Add a concise, natural Simplified Chinese value at the same path. TypeScript rejects an incomplete shape.
3. Use `useTranslation(namespace)` at the presentation boundary. Do not pass a global translation object through
   components.
4. Keep provider IDs, protocol keys, technical logs, and canonical music metadata out of resources.
5. Prefer interpolation and `Intl` formatting to concatenated grammatical fragments. Counts, byte sizes, and
   other numeric UI values use the resolved locale.
6. Add a test when the key controls fallback, switching, accessibility text, or error-code presentation.

Rust and HTTP API errors remain stable technical contracts. React translates structured provider/playback codes
at the UI boundary; diagnostic logs remain technical English.
