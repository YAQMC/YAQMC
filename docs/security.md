# Security & privacy

> [简体中文](zh-CN/security.md) | **English**

This page captures YAQMC's privacy contract and the layered mitigations that
enforce it. It is intentionally narrow: the runtime and reporter promise
concrete, testable behaviors, and every one of them is exercised by an
automated test.

## Runtime privacy contract

- **Zero telemetry.** The application never phones home. There is no analytics
  ID, no crash reporter beacon, no "usage statistics" toggle. The only network
  activity is the user-facing music provider and, when the user explicitly
  opens an Issue, the browser they launched.
- **No credential storage outside the OS keyring.** QQ Music cookies live in
  the platform credential store (`credentials/PlatformCredentialStore`) and
  never touch the log file, the diagnostic snapshot, or any bundled file.
- **No third-party CDNs.** The frontend ships only local assets.
- **User-owned identity.** The session ID generated by `logging.rs` is
  regenerated on every launch and never persisted; nothing correlates a user
  across installs.

## Redaction

`RedactingWriter` wraps the file sink of the tracing subscriber. Every line
that touches disk passes through `scrub_high_risk_patterns`, which redacts:

- `Cookie` header and `Authorization` header values,
- OAuth codes and bearer tokens,
- QQ Music `qm_keyst`, `qrsig`, `ekey`, `vkey`, `p_skey`, `p_uin`, `uin`,
- `authenticated=` and `vkey=` playback URL parameters,
- password-like values (`password=`, `passwd=`, `secret=`, `token=`),
- the local API secret token,
- home directory paths (rewritten to `<USER_HOME>`).

Structured tracing fields are preferred over string interpolation because the
Rust type system can enforce that we never pass raw secrets through
`tracing::info!("... {token}")`.

Automated tests in `crates/yaqmc-core/src/logging.rs` feed every representative
sensitive pattern through the writer and assert that the emitted output
contains only `[REDACTED]` markers.

## Diagnostic bundle safety

The bundle exporter (`crates/yaqmc-core/src/diagnostics.rs::export_bundle`) runs a
second-pass scan over every text file it is about to ZIP up. The
`RedactionReport` written into `redaction-report.txt` records:

- scanner version (`v1` today),
- number of files scanned,
- number of values redacted,
- list of unresolved high-risk patterns (empty in the healthy case).

If any high-risk pattern survives the pass, the exporter refuses to create a
"safe" bundle unless the user explicitly overrides. The override toggle is
intentionally not shipped in the initial UI — maintainers who need it can
enable it through the diagnostic snapshot's raw command payload.

The bundle never contains:

- cookies, `qm_keyst`, `qrsig`, `ekey`, `vkey`, OAuth codes, bearer tokens;
- account session files or SQLite blobs;
- raw authenticated HTTP captures;
- the local API secret token;
- QR-login secrets;
- real usernames — home directories are rewritten to `<USER_HOME>`.

Bundle SHA-256 is surfaced in the UI so a maintainer receiving a copy can
verify integrity.

## Issue reporter safety

- **No GitHub token, ever.** The reporter never asks for a Personal Access
  Token, never stores credentials, and never contacts the GitHub API.
- **Manual submission only.** YAQMC opens GitHub in the user's default
  browser with a prefilled Issue Form; the user reviews and clicks Submit
  themselves.
- **Scoped opener.** `openIssueUrl` first invokes Core's `validate_open_url`
  check and then crosses Electron Main's `shell.openExternal` allowlist in
  `apps/desktop/main/open-external.ts`.
- **No browser cookie access.** YAQMC does not read the system browser
  cookie jar, does not embed a browser view for this workflow, and does not
  automate any DOM action.

## Threat surface for logs and bundles

- A user pasting log contents into a public forum: mitigated by pre-write
  redaction, second-pass export scan, and the `[REDACTED]` sentinel.
- A user attaching an old rotated log after a credential change: mitigated by
  the same second-pass scan.
- A user unknowingly attaching the wrong bundle: mitigated by the SHA-256
  surface and the "Reveal bundle" action.
- A user opening an attacker-controlled URL that pretends to be the reporter:
  blocked by the narrow Core Issue-prefix check plus Electron Main's HTTPS
  allowlist.

## Coordinated disclosure

Security bugs are not filed through the Issue Reporter. They flow through the
private "Security advisory" contact link exposed in
`.github/ISSUE_TEMPLATE/config.yml` and documented in the repository's
`SECURITY.md`.
